- **Rule details — Zoran, Sabrina, Dimitar are NOT exempt.** Chris clarified mid-session: those identities cover a spouse, so they have `min_checkins_required = 6` on their `wellpass_identities` row (not 3). The score logic uses each identity's own Min, so they naturally need 6 sign-ins per week to break even — no special-casing required in code.
- **Type changes:** `WellpassWeeklyBookings` interface added; `WellpassIdentityRow.weekly_bookings` field added (each row carries year/week_number/booking_count). Helper `joinLoads`-style match against `wellpass_weekly_checkins` row by `(year, week_number)` key.
- **UX note flagged in conversation:** Chris asked whether posting two parallel WODs at 18:30 + 18:31 is safe. Answer: yes, mechanically. The `(date, time)` uniqueness check at [app/api/sessions/generate-weekly/route.ts:91](app/api/sessions/generate-weekly/route.ts#L91) (and the dupe-cleanup at [hooks/coach/useWODOperations.ts:650](hooks/coach/useWODOperations.ts#L650)) treats them as distinct rows; each gets its own capacity / bookings / score entry / locks. Only watch-out: athletes see two near-identical times on `/member/book` — clear per-session titles avoid confusion. Wellpass household 1-booking-per-week rule still counts them as separate bookings, so a restricted household trying to book both will get rejected on the second.
